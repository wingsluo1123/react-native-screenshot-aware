# react-native-screenshot-aware HarmonyOS (OpenHarmony) Adaptation

> This document describes how react-native-screenshot-aware is adapted to the OpenHarmony / HarmonyOS platform: capability, version mapping, and integration steps. Chinese version: [README.OpenHarmony_CN.md](./README.OpenHarmony_CN.md).

## 1. Capability

This library detects **screenshot events in real time** inside a React Native app. The HarmonyOS adaptation keeps the exact same public API as iOS / Android (`useScreenshotAware`, `addListener`, `removeAllListeners`) and the same event name `ScreenshotAwareEvent`.

### Platform implementation comparison

| Platform | Mechanism | Notes |
| -------- | --------- | ----- |
| iOS | `UIApplicationUserDidTakeScreenshotNotification` | System-level screenshot notification |
| Android (14+) | `Activity.registerScreenCaptureCallback` + `DETECT_SCREEN_CAPTURE` permission | Android 14 API, API 34+ only |
| **OpenHarmony/HarmonyOS** | `display.on('captureStatusChange')` (API 12+) | Fires when the screen content is being captured (screenshot / projection / screen recording) |

> ⚠️ **Capability difference**: on HarmonyOS, `@ohos.screenshot` is a system API (requires `ohos.permission.CAPTURE_SCREEN`, system apps only), so third-party apps cannot use it directly. This adaptation instead uses `@ohos.display`'s `captureStatusChange` event (API 12+, available to third-party apps), which reports `true` whenever the screen starts being captured — **screenshot, projection, or screen recording**. In other words, on HarmonyOS the event also covers projection/screen-recording scenarios (similar to the iOS notification mechanism, but different from the Android 14 screenshot-only API). Please design your business logic accordingly.

## 4. Integration

### 4.1 Install dependencies

```bash
npm install react-native-screenshot-aware
# RNOH is additionally required in the HarmonyOS project (matching front-end version)
npm install @react-native-oh/react-native-harmony@0.84.3 @react-native-oh/react-native-harmony-cli@0.84.3
```

Inside the `entry` directory of the HarmonyOS project (version aligned with the front-end package):

```bash
ohpm i @rnoh/react-native-openharmony@0.84.3
```

### 4.2 Autolinking (recommended)

This library declares `harmony.autolinking` in its `package.json`:

```json
{
  "harmony": {
    "autolinking": {
      "ohPackageName": "@rnoh/react-native-screenshot-aware",
      "etsPackageClassName": "ScreenshotAwarePackage"
    }
  }
}
```

In the RNOH project run `link-harmony` (usually triggered automatically by the hvigor plugin at build time, or run manually):

```bash
npx @react-native-oh/react-native-harmony-cli link-harmony
```

The command installs the HAR and registers `ScreenshotAwarePackage` in the generated `RNOHPackagesFactory.ets`.

### 4.3 Manual integration (without Autolinking)

1. Add the dependency in the HarmonyOS project's `oh-package.json5`:

   ```json5
   {
     "dependencies": {
       "@rnoh/react-native-screenshot-aware": "file:../node_modules/react-native-screenshot-aware/harmony/screenshot_aware"
     }
   }
   ```

2. Register the package in `entry/src/main/ets/RNPackagesFactory.ets`:

   ```typescript
   import { RNPackageContext, RNPackage } from '@rnoh/react-native-openharmony/ts';
   import { ScreenshotAwarePackage } from '@rnoh/react-native-screenshot-aware';

   export function createRNPackages(ctx: RNPackageContext): RNPackage[] {
     return [new ScreenshotAwarePackage(ctx)];
   }
   ```

> Note: with Autolinking, `RNOHPackagesFactory.ets` is generated by `link-harmony` — no manual edit needed.

## 5. Usage

The API is identical to iOS / Android:

```tsx
import { useScreenshotAware } from 'react-native-screenshot-aware';

function MyComponent() {
  useScreenshotAware(() => {
    console.log('Screenshot/capture detected!');
  });
  return <View />;
}
```

Class components or non-React contexts:

```tsx
import ScreenshotAware from 'react-native-screenshot-aware';

useEffect(() => {
  const subscription = ScreenshotAware.addListener(() => {
    console.log('A screenshot was taken!');
  });
  return () => subscription.remove();
}, []);
```

## 6. Notes

- HarmonyOS does not support the `DETECT_SCREEN_CAPTURE` permission nor `@ohos.screenshot` (system API); do **not** declare related permissions in `module.json5`;
- `captureStatusChange` reports `true` when the screen starts being captured (screenshot / projection / screen recording) — close to the iOS notification semantics, but it **cannot distinguish screenshots from screen recordings**;
- Events are emitted through RNOH's `emitDeviceEvent` mechanism; the listener is automatically unregistered in the TurboModule's `__onDestroy__` to avoid leaks;
- Verify on a real device (API 12+); events will not fire on emulators / older API levels.
